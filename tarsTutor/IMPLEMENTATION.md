# TarsTutor implementation

The retained application is React 19 + Vite + Excalidraw. The retained Python service is FastAPI, Gemini/LangGraph and SQLite. The original board and conversation stay available at `/board`.

The classroom adds a separate persisted lesson resource without breaking existing conversation endpoints. A plan is generated first, followed by independently validated teaching segments. The first playable segment opens the classroom while later segments generate. Generation stages reflect completed backend operations. Reloads recover the saved lesson; retries reuse its ID.

The browser converts validated drawing instructions on a 1000 × 700 lesson plane into native editable Excalidraw objects. The full original editor toolbar now appears inside the classroom. Reveal fractions follow actual narration audio time; student edits, deletions and z-order changes are preserved when playback continues. Each chapter's board and inserted images are saved in IndexedDB. Questions pause the main audio and keep its position. Quizzes are graded on the server; private answer keys never enter the lesson response.

Gnani STT and TTS are accessed exclusively through the backend. Study materials are validated and extracted before they are included as untrusted context in generation. No provider credentials are sent to the browser.

Classroom voice and typed questions now carry a native scene export as multimodal context. Selection takes priority, followed by student additions/edits and nearby labels; a clean light image includes handwriting and embedded images. Voice freezes this context before recording starts. The backend validates image format/dimensions/size, labels the current board separately from source images, and instructs Gemini to prioritize the actual drawing over unrelated lesson topics. Only the response and request hash persist. Drawing replies retain the original editor scene, speak the explanation, and leave the main lesson paused. Snapshot/network failures are visible and retryable. Script/language detection selects matching STT/TTS routes.

`drawingAnswer.ts` turns drawing replies into native objects next to the captured sketch. Client-only anchors follow the original element IDs if the student moves the sketch while waiting. Collision checks avoid other board objects, including prior answers and upcoming lesson content. A single undo step appends the answer; retries do not duplicate it. The viewport fits the sketch and solution, and IndexedDB stores the new objects with the chapter. Main lesson playback/reset preserves these answer objects. Missing model visuals fall back to the written reply. Anchors remain associated with the original snapshot through retries and voice transcription.

`useTutorTheme.tsx` shares a persisted light/dark preference across all tutor routes and the native editor's `theme` / `onThemeChange` APIs. `tutor-theme.scss` defines semantic surface, text, accent, feedback and focus colors. The composer is a dedicated accessible `QuestionComposer.tsx`, with controlled multiline input, IME-safe keyboard submission, recording and busy states, and grouped actions. An owner-window ResizeObserver reserves room for the footer as the input grows. Palette contrast was checked numerically; motion honors the system's reduced-motion preference. Board storage now reopens a cached connection once on InvalidStateError and clears recovered save-error banners.

Validation covers backend schema/progress/recovery/grading, speech protocol and error handling, frontend playback behavior, TypeScript, the production build, and live generation for linear regression and a second subject when provider access is available. Final results and environment limits are documented in `VERIFICATION.md`.
