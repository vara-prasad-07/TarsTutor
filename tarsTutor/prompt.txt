## 3. Core AI Lesson Generation

Implement a genuine AI-driven lesson generation pipeline.

When a student submits a topic, the system should:

1. Analyze the student's request.
2. Identify the subject and learning objectives.
3. Generate a logical lesson structure.
4. Divide the lesson into manageable teaching steps.
5. Generate accurate explanations and relevant examples.
6. Prepare whiteboard instructions and visual elements.
7. Generate narration text for each teaching step.
8. Create relevant questions to assess understanding.
9. Start the lesson once the first teaching segment is ready.

Design a structured lesson format rather than relying on unstructured AI-generated paragraphs.

For example, each lesson segment could contain:

- Segment ID
- Lesson title
- Learning objective
- Narration text
- Whiteboard drawing commands
- Equations or diagrams
- Estimated narration duration
- Quiz or interaction details
- Transition to the next segment

Use a validated schema so the frontend can reliably render AI-generated lessons.

Support different subjects, including mathematics, science, programming, and general educational topics.

## 4. Interactive Whiteboard Engine

This is the most important component of TarsTutor.

Build a reusable whiteboard engine capable of rendering:

- Handwritten-style text.
- Mathematical equations.
- Graphs and coordinate systems.
- Geometric shapes.
- Arrows and annotations.
- Tables and step-by-step calculations.
- Educational diagrams.
- Code examples with syntax highlighting.

The whiteboard must support progressive rendering.

For example, when teaching linear regression:

1. Display the lesson title.
2. Explain what linear regression means.
3. Draw an X-Y coordinate system.
4. Plot example data points.
5. Draw a regression line.
6. Introduce the equation `y = mx + b`.
7. Explain slope and intercept.
8. Walk through a prediction.
9. Ask the student a short quiz.

Each visual action must be coordinated with the spoken explanation.

Use an appropriate rendering architecture such as SVG, Canvas, or an existing whiteboard library, depending on what best fits the codebase.

Avoid fragile hardcoded animations that only work for one topic.

The engine must work with dynamically generated lessons.

## 5. Gnani AI Speech Integration

Use the existing Gnani AI configuration for both speech recognition and speech synthesis.

### Text-to-Speech

- Convert lesson narration into natural AI speech.
- Play audio alongside whiteboard animations.
- Support pause, resume, and replay.
- Synchronize visuals with audio using actual timing information where available.
- Handle audio buffering and network failures.
- Cache generated audio when appropriate.

### Speech-to-Text

- Allow students to ask questions using their microphone.
- Capture voice input with appropriate microphone permissions.
- Convert the audio into text using Gnani AI STT.
- Send the transcribed question to the AI tutor.
- Generate a contextual answer.
- Speak the response using Gnani AI TTS.
- Update the whiteboard when a visual explanation is useful.

**Critical requirement:** When a student interrupts the lesson, pause the ongoing lesson, answer the question, and then allow the student to resume from the correct position.

Do not let overlapping audio streams play simultaneously.

## 6. AI Tutor Conversation and Context

The AI tutor must behave like a real teacher, not a basic question-answer chatbot.

It should:

- Remember the current lesson topic.
- Understand which concept is currently being explained.
- Answer questions using the lesson context.
- Explain difficult concepts in simpler language.
- Provide additional examples when requested.
- Adapt explanations to the student's level.
- Ask relevant questions to check understanding.
- Resume the main lesson naturally after an interruption.

Example:

**AI Tutor:** "The slope tells us how much the predicted value changes when X increases by one unit."

**Student:** "Can you explain slope with a real-life example?"

**AI Tutor:** "Of course. Imagine you earn ₹100 for every hour you work..."

The whiteboard should then display a small example while the tutor explains.

Maintain session-level lesson history and conversation context.

## 7. Interactive Quiz System

Include short questions during lessons.

Support:

- Multiple-choice questions.
- Numerical answers.
- Simple text-based answers.
- Immediate feedback.
- Explanations for incorrect responses.
- Continued teaching after the answer.

For example:

**Question:** A regression line has residuals of +5 and -5. What is their contribution to the sum of squared residuals?

Options:

- 0 points squared
- 10 points squared
- 50 points squared

Correct answer: 50 points squared.

The tutor should explain:

`5² + (-5)² = 25 + 25 = 50`

Quiz questions must be generated from the actual lesson content, not hardcoded examples.

## 9. Performance and Reliability

Optimize for a responsive learning experience.

Where supported by the architecture:

- Generate lesson segments incrementally.
- Begin playback before the entire lesson is generated.
- Preload the next lesson segment.
- Cache reusable generated assets.
- Avoid unnecessary frontend re-renders.
- Handle API rate limits and timeouts.
- Prevent duplicate lesson-generation requests.
- Implement safe cancellation and retry behavior.
- Recover gracefully from TTS, STT, or AI generation errors.

Provide visible loading and failure states.

Do not block the entire interface while preparing later lesson segments.
